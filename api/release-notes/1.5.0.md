# Site Customizations

A few weeks ago, I was asked by SONS to see if we can morph the DinnerBears.Com website to support their meetings, with today's release, we are close to that being available. I've worked to adjust all of the hard coded branding for Dinenrbears to something that can be configured via the application.  
As a bonus, we now have the ability to support Pot Luck Dinners, like the one we have coming up in just over a week. Please let me know if you see any issues with the branding.

## Site Customization & Branding

- Admins can set the site name, tagline, colors, and logo/splash/icon images right from
  Site Settings — changes apply instantly, no rebuild
- The home page hero, "How it works", and "Our Story" sections are fully editable from
  the admin panel — rewrite them, or clear one to hide it, with no code change
- Upload a home-page "Story" image and manage the preset profile avatars members can
  choose from
- Terms of Service, Privacy Policy, and the "Our Story" page can be updated by an admin
  at any time — no code change or app update required
- Site colors now flow through the whole interface automatically from your chosen
  primary color

## Group Terminology & Feature Toggles

- Rename the core terms the site uses — "Restaurant", "Dinner", and "{{points}}" — to
  whatever fits your group
- Turn specific features (Ratings, the {{points}} Leaderboard, the Merch store, the
  Members directory) on or off to match what your group actually wants to offer
- Every email a member receives — invitations, RSVP confirmations, reminders, and
  calendar invites — now uses your group's own name and branding instead of a
  hardcoded default

## Location Privacy & Residences

- New events can default to your group's usual day and time
- {{locations}} can keep their address hidden until a member RSVPs "Going", and can be
  marked as a private residence so they're treated as a home rather than a business
- Private {{locations}} now keep their photos hidden too, not just the address, until
  a member RSVPs "Going" — matching how private {{events}} already work

## Membership Fees & Residence Potlucks

- Admins can require an active membership to RSVP "Going" — turn it on in Site
  Settings, then mark each member's membership status and expiration from the Members
  page. Every member's first {{events}} is always free before this kicks in
- Memberships run on a calendar year and expire January 1
- For {{events}} at a residence, members can say what they're bringing when they RSVP
  "Going" — it shows right next to their name on the guest list

## Reliability Fixes

- Fixed a login issue where signing in could occasionally appear to fail even though
  it had actually worked, requiring a second attempt
- {{locations}} and {{events}} with multiple photos now consistently show the same
  cover photo everywhere, instead of sometimes showing a different one from page to
  page
- Old bookmarked or shared {{locations}} links now redirect to the right page instead
  of showing an error
- Fixed an issue where saving Site Settings with several changes at once could fail
  partway through and need a retry
- Transactional emails now always show your group's own uploaded logo instead of the
  default one

## Built for Other Groups, Not Just Us

The whole site can now be relaunched under a different group's name, colors, and
terminology while keeping the same look, feel, and features — so other organizations
can run their own version without starting from scratch. Release notes like this one
are now generated automatically as part of shipping updates, so what's new is always
accurate and up to date.
