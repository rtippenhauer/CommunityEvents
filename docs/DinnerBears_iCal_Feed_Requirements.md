# DinnerBears — iCal Feed Requirements
**Document:** DinnerBears_iCal_Feed_Requirements.md  
**Version:** 1.0  
**Status:** Ready for Claude Code  
**Related Requirements:** REQ-NEW-16 through REQ-NEW-22

---

## Overview

Enable DinnerBears members to subscribe to a personal iCal feed so upcoming dinners automatically appear in Apple Calendar, Google Calendar, Outlook, or any iCal-compatible calendar app. Each calendar event includes a deep link back to the DinnerBears event detail page for RSVP and details. A companion email attachment flow (Phase 2) delivers native Accept/Decline prompts in Apple Mail.

---

## Background & Constraints

### What iCal Can and Cannot Do

| Capability | Supported |
|---|---|
| Auto-populate events into calendar apps | ✅ Yes |
| Show restaurant name, address, date/time | ✅ Yes |
| Deep link back to DinnerBears for RSVP | ✅ Yes (URL property) |
| Rich HTML card / images inside event | ❌ No — plain text only |
| Real-time push updates | ❌ No — poll-based (~15 min) |
| Capture RSVP response back from calendar | ❌ No — requires email attachment flow |

### Polling Behavior
Apple Calendar refreshes subscribed feeds approximately every 15–60 minutes. This is not configurable by the server beyond setting a hint via `REFRESH-INTERVAL`. For time-sensitive changes (cancellations, venue changes), push notifications and email remain the primary communication channel.

## Phase 1 — iCal Subscription Feed

### REQ-NEW-16: Personal iCal Feed Endpoint

**Endpoint:** `GET /api/v1/calendar/feed.ics`

**Authentication:** Token-based via query parameter (calendar apps cannot send headers).
- Generate a unique, non-guessable `calToken` per member (UUID v4, stored in `users` table)
- URL format: `https://dinnerbears.com/api/v1/calendar/feed.ics?token=<calToken>`
- Token does not expire automatically but can be regenerated by the member (invalidates old URL)
- Token is independent of the member's session/OAuth tokens

**Feed Contents:**
- Include all events the member has been invited to
- Include events where the member's RSVP status is: `attending`, `maybe`, `declined`, `pending`
- Exclude events that have been cancelled AND are more than 7 days in the past
- Include future cancelled events so members see the cancellation on their calendar

**Feed Metadata:**
```
PRODID:-//DinnerBears//DinnerBears Calendar//EN
VERSION:2.0
CALNAME:DinnerBears
CALDESC:Your upcoming DinnerBears dinners
REFRESH-INTERVAL;VALUE=DURATION:PT15M
X-PUBLISHED-TTL:PT15M
```

### REQ-NEW-17: iCal Event Properties

Each event in the feed must include the following iCal properties:

| Property | Value | Notes |
|---|---|---|
| `UID` | `dinnerbears-event-{eventId}@dinnerbears.com` | Stable across updates |
| `SUMMARY` | `DinnerBears Dinner at {restaurantName}` | |
| `DTSTART` | Event date/time in UTC | Format: `YYYYMMDDTHHMMSSZ` |
| `DTEND` | DTSTART + 2 hours | Default duration |
| `LOCATION` | `{restaurantName}, {address}, {city}, {state} {zip}` | Renders as maps link on iPhone |
| `DESCRIPTION` | See REQ-NEW-18 | Plain text only |
| `URL` | `https://dinnerbears.com/events/{eventId}` | Deep link for RSVP |
| `ORGANIZER` | `CN=DinnerBears:mailto:noreply@dinnerbears.com` | |
| `STATUS` | `CONFIRMED` or `CANCELLED` | Set to CANCELLED for cancelled events |
| `LAST-MODIFIED` | Timestamp of last event update in UTC | Enables calendar app cache invalidation |
| `SEQUENCE` | Increment integer on each event update | Signals update to calendar apps |

---

### REQ-NEW-18: Event Description Format

The `DESCRIPTION` field must be plain text, formatted as follows:

```
DinnerBears Dinner

🍽 {restaurantName}
{streetAddress}
{city}, {state} {zip}

📅 {DayOfWeek}, {Month} {Day} at {Time} ({timezone})

🤝 Your RSVP: {ATTENDING | MAYBE | DECLINED | PENDING}
👥 {confirmedCount} attending

Tap to view details and RSVP:
https://dinnerbears.com/events/{eventId}

---
Questions? Reply to hello@dinnerbears.com
To unsubscribe from this calendar, visit your DinnerBears account settings.
```

Notes:
- Emoji are supported in `DESCRIPTION` on Apple Calendar and Google Calendar
- Line breaks use `\n` escaped per iCal spec (`\n` in the property value)
- Long lines must be folded per RFC 5545 (max 75 octets per line, continued with CRLF + whitespace)

---

### REQ-NEW-19: Feed Caching

- Cache the generated `.ics` file per member for 15 minutes
- Invalidate cache immediately when:
  - An event the member is invited to is created, updated, or cancelled
  - The member's RSVP status changes
  - The member regenerates their calendar token
- Use the member's `calToken` as the cache key
- Return `Content-Type: text/calendar; charset=utf-8`
- Return `Content-Disposition: inline; filename="dinnerbears.ics"`

---

### REQ-NEW-20: Calendar Token Management (Member Settings UI)

Add a **Calendar Subscription** section to the member's account settings page.

**Display:**
- A copyable subscription URL (masked, with a copy-to-clipboard button)
- Instructions: "Paste this link into your calendar app to subscribe to your DinnerBears events."
- A "Regenerate Link" button with a confirmation warning: "This will break your existing calendar subscription. You will need to re-subscribe with the new link."
- A platform guide with setup links:
  - Apple Calendar: Settings → Calendar → Accounts → Add Account → Other → Add Subscribed Calendar
  - Google Calendar: Other Calendars → From URL
  - Outlook: Add Calendar → Subscribe from web

**Backend:**
- `POST /api/v1/members/me/calendar-token/regenerate` — generates new UUID, invalidates old token, returns new URL
- Token stored in `users.calendar_token` column (VARCHAR 36, nullable, unique index)

## Phase 2 — Email .ics Attachment (Native RSVP Prompt)

### REQ-NEW-21: .ics Attachment on Event Invitation Emails

When a new dinner invitation email is sent to a member (via Resend), attach a `.ics` file to the email.

**This enables Apple Mail to render a native "Accept / Decline / Maybe" prompt** for the event, which is the closest available experience to an in-calendar RSVP card.

**Attachment properties:**
- Filename: `dinnerbears-dinner.ics`
- Content-Type: `text/calendar; method=REQUEST`
- The `METHOD:REQUEST` property in the file signals that this is an invitation (not just an informational event)
- Include `ATTENDEE` property for the recipient:
  ```
  ATTENDEE;CN={memberName};RSVP=TRUE:mailto:{memberEmail}
  ```

**Important limitation:** When the member taps Accept/Decline in Apple Mail, the response goes to the `ORGANIZER` email address (`noreply@dinnerbears.com`). This must be a monitored inbox or forwarded to a processing endpoint.

---

### REQ-NEW-22: RSVP Email Response Processing (Optional — Phase 2b)

If a member RSVPs via the Apple Mail prompt, their calendar app sends a reply email to the `ORGANIZER` address containing a `.ics` file with `METHOD:REPLY` and the attendee's response (`ACCEPTED`, `DECLINED`, `TENTATIVE`).

**To process these responses automatically:**
- Configure Cloudflare Email Routing to forward `calendar-rsvp@dinnerbears.com` to a webhook or processing endpoint
- `POST /api/v1/calendar/rsvp-reply` — parses the inbound email, extracts the iCal reply, maps the attendee email to a member, updates their RSVP status
- Map iCal responses to DinnerBears RSVP status:

| iCal PARTSTAT | DinnerBears Status |
|---|---|
| `ACCEPTED` | `attending` |
| `DECLINED` | `declined` |
| `TENTATIVE` | `maybe` |

**Note:** This is complex to implement reliably (parsing inbound email with attachments) and is lower priority. Manual RSVP via the deep link URL is the primary RSVP path. Phase 2b should only be built if demand warrants it.

## Database Changes

### `users` table — add column:
```sql
calendar_token VARCHAR(36) NULL UNIQUE COMMENT 'UUID for iCal feed authentication';
```

Generate tokens lazily (on first visit to calendar settings) or eagerly (on account creation).

## Security Considerations

- The `calToken` grants read access to the member's event list — treat it as sensitive
- Do not expose member names, email addresses, or other members' RSVP statuses in the feed
- The feed should only show event-level data: name, location, time, deep link, and the requesting member's own RSVP status
- Rate-limit the feed endpoint: max 10 requests per token per minute
- Log feed access (token, timestamp, IP) for audit purposes

## Out of Scope

- Push/real-time calendar sync (not supported by iCal spec)
- Rich HTML or image content inside calendar events
- CalDAV (two-way sync protocol) — significant infrastructure investment, not warranted at current scale
- Google Calendar API integration (separate implementation path, not iCal)
